§5.3#49 · Optional Google site search

Encoding example
Terms: garden & "new year" SiteBaseUrl: https://<site>/ q=garden+%26+%22new+year%22+site%3A<site>
Rules
  • Exactly one trusted site: clause; never trust one typed by the visitor
  • Bound input is never mutated, so repeat searches don't stack clauses
  • Works by keyboard and with JavaScript off; Back button behaves
  • Only public search terms go to Google: no identity, cookies, or email
  • Category filter stays separate

New setting via 10.07.00.sql, guarded insert of GoogleSiteSearchEnabled = False.

§9Security and privacy requirements

Archive traversalEvery entry resolved under a canonical package folder; no absolute, drive, .., backslash, duplicate or symlink entries.
No code executionCSS and static assets only; HTML, Razor, JS, DLL, EXE and content-type mismatches rejected.
CSS privacyNo remote url(), so a theme can't fingerprint visitors through a third party.
Upload availabilitySize, entry and ratio limits enforced during extraction; partial folders deleted on failure.
Path storageClients send package IDs only; the server computes every physical path.
Admin authorizationPage, controller and service all require Administrators; antiforgery validated.
Metadata injectionAttributes encoded; summary and content normalized to plain text.
Query injectionQuery encoded once; visitor-supplied site: never trusted.
No image fetchSocial image URLs are built, never fetched or resolved server-side.
Test dataPlaceholders like <site>; no real emails, tokens, hostnames or IPs committed.
CredentialsCI has no real Google, Stripe or SMTP keys; manual runs report pass/fail only.
Active theme failureIntegrity verified before activation; prior active setting kept on any failure.
